    01▶ 0:00 – 17:38

    How the internet started

    A network is computers connected together. The internet is a network of those networks, spread across houses, cities and countries.

    Computer network

    Two or more devices connected so they can share data.

    Internet

    A global collection of connected computer networks. It runs mostly through cables, including cables under the sea.

    Timeline

    !
    Instructor slip. The video names MIT, Stanford, UCLA and Utah as ARPANET's first four sites, running TCP. The first four were really UCLA, SRI (Stanford Research Institute), UC Santa Barbara and Utah. ARPANET started on a protocol called NCP and switched to TCP/IP in 1983. The "COMPUTER = Commonly Oriented Machine…" full form is a school joke, not a definition.

    Why protocols exist

    Different data needs different rules, and everyone has to follow the same rules or apps can't understand each other. Those rules are protocols.

    Email

    Follow set steps

    Send to a server, the receiver downloads it, then reads it.

    Video call

    Speed first

    Dropping a few frames is fine.

    Secret documents

    100% must arrive

    No data may be lost.

    World Wide Web

    Linked documents

    Researchers wanted papers that link to other papers. WWW gives every document a URL and links them with hyperlinks; the pages live on web servers. The first website is still up at info.cern.ch.

    Who makes the rules

    Internet Society + RFCs

    New ideas are proposed as an RFC (Request for Comments). Anyone can submit one. Extra context: the IETF, under the Internet Society, writes the standards.

    02▶ 17:38 – 42:25

    Clients, servers, IP addresses and ports

    An IP address finds the device. A port number finds the app on that device. This chapter sets up the ideas the rest of the course goes deeper into.

    TCP

    Must arrive intact

    Transmission Control Protocol. Makes sure data reaches its destination uncorrupted.

    UDP

    Fast, may lose some

    User Datagram Protocol. Used for video calls.

    HTTP

    Web pages

    HyperText Transfer Protocol. Rules for how browsers request and servers reply.

    Data never travels in one piece. It is cut into small chunks called packets.

    IP address: the phone book

    IP address

    A number that identifies every device on the internet. Format X.X.X.X, each X from 0 to 255.

    Analogy from the video

    You tap "John" and your phone dials the number saved under that name. Typing google.com works the same way: the name is turned into an IP address.

    curl ifconfig.me -s shows your public IP.

    One router, many devices

    !
    Instructor slip. NAT is said once as "network access translator". The real name is Network Address Translation (Chapter 10).

    Port numbers 34:23

    Problem

    The reply reached your laptop. But is it for Chrome, MongoDB, your own server or a game chat? All of them share the laptop's IP.

    Answer

    IP address → device. Port → application. Ports are 16-bit numbers, so there are 216 = 65,536 of them (0–65,535).

    Speed and links

    UnitBits per second
    1 kbps10³ = 1,000
    1 Mbps10⁶ = 1,000,000
    1 Gbps10⁹
    Remember

    Mbps is megabits, not megabytes. Divide by 8 for MB/s. Upload = you send; download = you receive.

    Guided links follow a wire (Ethernet, fibre). Unguided links don't (Wi-Fi, Bluetooth).

    Application layer: architectures, devices, protocols, HTTP

    Where users meet the network. Apps connect either through a central server or directly as peers, and every exchange follows a protocol.

    Client–server vs peer-to-peer

    Servers need
    • A reliable IP that clients can reach
    • High availability
    • Big companies use data centers: static IPs, always-on links, high upload speed
    • Overload crashes sites: exam results day, the PS5 pre-order launch
    P2P
    • No central server; devices connect directly
    • Scales very fast, decentralised
    • Example: BitTorrent seeding
    • Hybrids exist: P2P plus a central database

    08Layer 7▶ 2:19:00

    DNS: the internet's phone book

    DNS (Domain Name System) turns names like google.com into IP addresses. It's split across many servers so no single database can take the whole internet down.

    Resolving google.com

    1. Local cache. Sites you've visited are remembered on your machine.
    2. Local DNS server, often your ISP's. Your ISP sees every site you look up, even in incognito.
    3. Root server, the first stop after local. It points to the right TLD.
    4. TLD server (.com, .org, .edu, or .in, .uk, .us) returns the IP.
    5. Your computer connects to google.com's server.
    i
    Extra context. In full detail the TLD server points to google.com's authoritative name server, which returns the final IP. DNS runs on UDP port 53.
    Domains

    You can't buy one, only rent it: you pay GoDaddy, GoDaddy pays ICANN.

    Own TLDs

    Google has .google; the video says Amazon has .fire.

    Try it

    dig google.com: domain information groper, a DNS lookup tool.

    09Layer 4▶ 2:32:24 – 3:13:40

    Transport layer: getting data to the right app

    The network layer moves data between devices. The transport layer moves it inside a device, between the network and the right application, and makes delivery reliable when needed.

    Multiplexing and demultiplexing

    Three tools for reliable delivery

    Checksum · detects corruption

    Sender computes a value from the data and attaches it. Receiver recomputes it the same way. Different value → corrupted.

    Timer · detects loss

    Start a timer on send; stop it when the ack arrives. Timer expires → resend. This is the retransmission timer.

    Sequence number · fixes order & duplicates

    Every segment is numbered, so a resent copy of #2 is spotted and dropped, and "my Hi Kunal name is" is put back in order.

    !
    Instructor slip. The video calls a checksum "a random string". It isn't random: it's calculated from the data, which is why the receiver can recompute and compare it.
    Congestion control

    Too many packets for the link, like too many cars at one gate, means some get lost. The transport layer slows the send rate using congestion-control algorithms built into TCP.

    UDP · User Datagram Protocol 2:54:00

    Personality
    • Connectionless: just sends
    • May not arrive, may change, may be out of order
    • Has a checksum, but ignores errors it finds
    • No feedback, so it's fast
    • Used for video calls, gaming, DNS

    TCP · Transmission Control Protocol 3:02:05

    Connection-oriented

    Handshake first, then data.

    Reliable

    Error control, retransmits lost data, keeps order.

    Congestion control

    Slows down when the network is busy.

    Full duplex

    Both sides can send at the same time.

    Two endpoints

    One connection joins exactly two computers.

    Used by

    HTTP, SMTP, POP3, IMAP, file transfer.

    The 3-way handshake 3:09:10

    In plain words
    1. "Can I connect?"
    2. "Sure, me too."
    3. "OK, connected."
    Why random sequence numbers?

    Predictable numbers would let attackers guess them and hijack connections. Random numbers are for security.

    Other flags: RST reset, FIN finish.

    !
    Instructor slips. The server's number (56) isn't "math on the client's 32"; each side picks its own random starting number, and only the ack is 32 + 1. The third message carries only ACK, not SYN. The video says "85" once before settling on 56.

    Network layer: routing and IP addresses

    Routers pass packets hop by hop until they reach the right network. Every packet carries the sender's and receiver's IP address the whole way.

    Hop-by-hop forwarding

    Routing tableForwarding table
    Many possible pathsOne chosen path
    The bigger tablePart of the routing table

    Control plane · 3:21:50

    Builds the routing tables. Static routing: routes typed in by hand, not adaptive. Dynamic routing: tables update themselves using algorithms like Bellman-Ford and Dijkstra, the same graph algorithms from DSA.

    ✓
    Your home router doesn't carry strangers' traffic. Hopping happens across ISPs' routers. Their tables hold blocks of addresses (subnets) assigned to ISPs like Airtel, Jio and Tata, not every device.

    IPv4 address, bit by bit

    32 bits written as 4 numbers of 8 bits each (0–255). That gives 232 ≈ 4.3 billion addresses. Type any address below to see its bits.

    network (subnet) bitshost bits

    Type an IPv4 address like 10.0.0.0/8, with four numbers from 0 to 255 and a prefix from 0 to 32.

    Classes, masks and subnets

    Subnet mask

    Masks the network part and leaves the host part free. In 192.168.1.1/24 the first 24 bits (192.168.1) are the subnet ID and 1 is the host.

    Addresses = 2(32 − prefix), so /24 gives 256.

    Loopback

    127.0.0.0/8 is reserved. 127.0.0.1 is localhost: your machine talks to itself, acting as client and server. Always up while the computer runs.

    Data link: MAC addresses, ARP and DHCP

    IP addresses get a packet to the right network. Inside a LAN, devices actually talk using MAC addresses, sending frames over a physical link.

    DHCP · new device joins
    1. Device connects to the router
    2. Asks the DHCP server for an IP
    3. Server picks one from its pool
    4. Device now has its IP
    MAC address

    Media Access Control: a 12-digit alphanumeric ID for one network interface. Your Wi-Fi and Bluetooth each have their own. Extra: 48 bits in hex, e.g. 3C:22:FB:9A:1E:07.

    You can block or allow devices by MAC. See yours with ifconfig.

    ARP: finding a MAC from an IP

    Data link also does
    • Framing: building and handling frames
    • Error detection
    • Works closely with the physical layer, handing it 0s and 1s
    • On the way back, the router maps the private IP to the right device's MAC
    Physical layer

    Bits become electrical, light or radio signals on cables and air. The video leaves the electronics for hardware study.

    R3Revision

    Pairs people mix up

    Internet vs WWW

    Network of networks, vs linked pages on top of it.

    HTTP vs TCP

    HTTP (L7) defines the request and response. TCP (L4) delivers the bytes. HTTP runs on TCP.

    Transport vs network layer

    Inside a device to the right app, vs between devices across networks.

    Segment · packet · frame · bits

    L4 L3 L2 L1

    MAC vs IP

    Physical, per interface, rewritten each hop, vs logical, end to end. ARP links them.

    IP vs port

    Which device, vs which app on it.

    Public vs private IP

    The router's world-facing address, vs DHCP-given inside addresses. NAT translates.

    Hub · switch · router

    L1 floods everyone · L2 forwards by MAC · L3 forwards by IP between networks.

    Checksum · timer · sequence

    Corruption · loss · order and duplicates.

    Seq vs ack number

    Labels my segment, vs the other side's last seq + 1.

    POP3 vs IMAP · SMTP

    POP3 downloads to one device, IMAP syncs all. SMTP only sends.

    Mbps vs MBps

    Megabits vs megabytes: divide by 8.
