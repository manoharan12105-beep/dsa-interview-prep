    Why every engineer needs Linux
    Servers, cloud machines, clusters and DevOps tooling run on Linux. When you connect to one there is no desktop, no mouse and no double-click: only a terminal. This chapter covers why, and the open-source idea behind it.
    

    Remember2 min revise
    • Linux is a free, open-source operating system. Almost every server, cloud VM and data cluster runs it.
    • Connect to a remote server and you get a black terminal: no GUI, so everything is a command.
    • Open source = the code is public; anyone can use, study, change and contribute to it, under a license.
    • Why Linux wins: free, secure by design (permissions), stable for years, customizable, light on old hardware, powerful CLI.
    • Viruses: rare, not impossible. Never say "Linux can't get viruses".
    

    Where Linux shows up in your job
    The course is aimed at data engineers, data analysts, data scientists, software engineers, testers and DevOps engineers. The instructor's point: whatever you build, it is deployed to a Linux server. On day one in a company you are handed an IP address, a username and a password, and you connect to a machine you will never see.
    Cloud providers (AWS, Google Cloud, Azure) create these machines for you: "8 GB RAM, 100 GB disk, 15 nodes". You connect over the network, so there is no graphical interface. You can't right-click → copy → paste. You type commands.
    Developers
    Web, mobile, full-stack
    Your app is deployed to a Linux server. You check logs, restart it and copy files there from a terminal.
    Data roles
    Data engineering & science
    Hadoop, Spark, Airflow and clusters all run on Linux. Jobs are scheduled and monitored from the shell.
    Infra
    Cloud & DevOps
    EC2 instances, containers, CI runners: all Linux by default.
    Career
    Interviews
    Linux itself gets 5–10 minutes, but lacking it shows up fast at work. Knowing it makes a strong first impression.
    ✓
    Story from the course T. The instructor describes a new teammate who was strong in Python and Java but had only used Windows servers. On a Linux team he struggled with basics like opening folders and running jobs. The skill gap was Linux, not coding.
    What "open source" means
    Open source
    Software whose source code is published so that anyone can use, study, modify and redistribute it, following the terms of its license.
    Python, MySQL, Hadoop and Spark are all open source. How do you prove it's yours? You publish the code (for example on GitHub) and release it under a license from a recognised body: the Apache Software Foundation, the Open Source Initiative (OSI) or the Free Software Foundation (FSF). The license keeps the record of who created it.
    The opposite is proprietary (closed-source) software: Oracle Database is the course's example. You pay for a license to use it and you can't see or change the code.
    Why give software away? Reputation and opportunity. The course tells the Hadoop story: its creator released it as open source, big companies' R&D teams adopted it, and that led to funding and a company. Even a small open-source library is a strong line on a résumé.

    Rarely, but it can. Linux is less targeted and its permission model limits what malware can do, which is why most Linux users don't run antivirus. Servers still use security and hardening tools. So the honest answer is "very rare, not zero".

    What Linux actually is: kernel, OS and distros
    Strictly speaking, Linux is only the kernel: the engine. Add a shell, utilities and a package manager and you get an operating system. Package all that up and you get a distro like Ubuntu.
    

    Remember2 min revise
    • Kernel = core engine: process scheduling, memory, I/O, devices. It translates between software and hardware.
    • OS = kernel + shell (bash) + utilities + package manager (+ GUI). Car analogy: an engine alone can't be driven.
    • Distro = a packaged Linux OS: Ubuntu, Debian, Fedora, CentOS, Arch, Kali. Commands are ~90% the same across them.
    • Linux vs Unix: Linux = Linus Torvalds, 1991, free, community-driven, runs anywhere. Unix = AT&T Bell Labs, 1969, mostly proprietary and vendor-driven (Solaris, AIX, HP-UX).
    • The course uses Ubuntu, the most common distro in industry.
    

    Is Linux really an OS?
    The twist the course points out: Linux is the kernel. Every operating system (Windows and macOS too) has a kernel at its heart. Like a car engine, a kernel alone isn't usable: you also need the steering, seats and dashboard. For an OS those are the utilities, tools, the shell (bash), the package manager and GUI tools.
    Operating system
    OS = kernel + utilities + tools + shell + package manager (+ optional GUI). Anyone can build an OS on the Linux kernel, which is why so many distros exist.
    What does the kernel do?
    CPU
    Process scheduling
    Decides which program gets the CPU and for how long.
    RAM
    Memory allocation
    Gives each program RAM and keeps them apart.
    I/O
    I/O operations
    Reads and writes disks, network and files.
    Devices
    Device management
    Talks to keyboards, disks and network cards through drivers.
    Analogy from the course: a manager between employees (the hardware) and customers (the software). You type input; the kernel makes sure both software and hardware understand it. Linux uses a monolithic kernel: all these services run together in one large kernel program.
    +
    Extra context. Three words people mix up. Terminal: the window you type into. Shell: the program that reads and runs your commands (bash, zsh, sh). Kernel: the core that the shell asks to do the real work. The shell is the "driver", the kernel is the "engine".

    Setting up: Ubuntu on Windows (WSL) and the filesystem
    Both courses assume a Windows laptop and use WSL, the Windows Subsystem for Linux. It installs Ubuntu like an app, with a real bash shell. Then: how Linux lays out its folders.
    

    Remember2 min revise
    • Enable Virtual Machine Platform + Windows Subsystem for Linux ("Turn Windows features on or off"), restart.
    • Command Prompt (as admin): wsl --install → Ubuntu installs → set a username and password. Don't forget the password: sudo asks for it.
    • Open Ubuntu from Start or from Windows Terminal's dropdown. Terminal colour doesn't matter.
    • Everything hangs off /. Your home is /home/<username>, shortcut ~.
    • Mac: use Terminal with bash. Real Linux: even better. B
    

    Install Ubuntu with WSL T 25:54 · B 3:00
    1. Search Windows for Turn Windows features on or off and open it.
    2. Tick Virtual Machine Platform and Windows Subsystem for Linux, press OK and let it apply changes.
    3. Restart Windows.
    4. Open Command Prompt as administrator and run wsl --install. This downloads and installs the Ubuntu distribution.
    5. When it finishes, create a username and password. The password is invisible as you type; that's normal.
    6. Open the Ubuntu app from Start (or pick Ubuntu in Windows Terminal's dropdown). You're in a bash shell.
    Command Prompt (Administrator)
    $ wsl --install

Ubuntu has been installed.

ubuntu@laptop:~$
    The Ubuntu terminal opens in violet; Windows Terminal is black. The instructor stresses that colour means nothing: a remote server will also be a black window. What matters is which OS the prompt is connected to.
    ✓
    Real-world tip. WSL isn't a full OS install: Ubuntu runs like an application inside Windows. Close the terminal and Linux stops (Ch 17 explains why that matters for background jobs).
    The Bash course B is also built around WSL, because it only uses command-line tools. On a Mac, use the Terminal app but make bash your shell (newer macOS defaults to zsh). The Bash course assumes basic Linux knowledge, which Chapters 4–9 give you.

    Absolute vs relative path
    An absolute path starts at / and works from anywhere: /home/ubuntu/abc/test. A relative path starts from where you are now: abc/test. . is the current folder, .. the parent, ~ your home.

    Your first commands
    Where am I, who am I, what machine is this, and how do I repeat what I typed? Plus the two keyboard habits that save the most time: Tab and ↑.
    

    Remember1 min revise

    Editing files in the terminal: vi, vim and nano
    There's no Notepad on a server. vi is on every Linux machine, so you must be able to open a file, type, save and escape. nano is the friendlier backup.
    

    Remember2 min revise
    • vi file opens (or creates) a file in Normal mode: you can't type yet.
    • i (or Insert key) → type → Esc → :wq save and quit. :q! quits without saving.
    • In Normal mode dd deletes the whole line. a appends after the cursor B.
    • Arrow keys print junk in plain vi → install vim: sudo apt-get install vim. You get colours and working arrows.
    • nano: type straight away → Ctrl+X → Y → Enter to save and exit.
    • Copy/paste in a terminal: Ctrl+Shift+C / Ctrl+Shift+V. In PuTTY: select = copy, right-click = paste.
    

    vi in five moves T 37:00
    1. vi hello.txt and Enter. The file opens (or is created). Typing now does nothing useful.
    2. Press i (or Insert). The bottom line shows -- INSERT --. Type your text.
    3. Press Esc to leave Insert mode.
    4. Type :wq and Enter: write (save) and quit. Check with ls.
    5. Changed your mind? Esc, then :q! quits and throws the changes away.
    ubuntu@linux: ~
    $ vi hello.txt  # i → type "Hi, welcome to the session" → Esc → :wq
$ ls
hello.txt
$ cat hello.txt
Hi, welcome to the session
    File extensions are just part of the name
    Linux doesn't need extensions; .txt, .csv, .py only help humans and tools tell files apart. But the extension is part of the file name: hello and hello.txt are two different files, so always type the full name (Tab helps).
    From vi to vim T 43:00
    Default vi on many systems is minimal: arrow keys print letters, everything is black and white. The fix is to install vim (Vi IMproved). After that, vi opens vim, arrows move, and Python or shell files are syntax-highlighted.
    ubuntu@linux: ~
    $ sudo apt-get install vim
[sudo] password for ubuntu:
vim is already the newest version.
    sudo
    "Superuser do": run one command with root (admin) permission, after entering your password. Installing software and changing system files need it. In companies you usually can't: you raise a ticket with a business justification and the admin team installs it.

    Creating, copying, moving and deleting files
    touch, cat, cp, mv, rm and echo are the verbs you'll use every day. Wildcards let one command act on many files. There is no recycle bin.
    

    Remember2 min revise
    • touch f.txt creates an empty file (real use: a "job done" marker file).
    • cat f prints a file. cp src dst copies. mv src dst moves and renames: there is no rename command.
    • rm f deletes forever. * matches anything: ls *.txt, rm hello*, rm * (everything!).
    • echo text prints; echo text >> f appends to a file; > overwrites.
    • cat a >> b copies a's content onto the end of b (creates b if missing).
    

    Create: touch T 55:30
    vi + :wq creates a file, but touch four.txt does it in one step. It creates an empty file (or just updates the timestamp if it exists).
    ✓
    How it's used T. Marker files. Data pipelines often touch a file such as job_2025-05-17.done when a job finishes. The next step checks whether that file exists before starting (Ch 24 shows the if [ -f file ] test). Hadoop and Spark write a _SUCCESS file for the same reason.
    Read: cat T 58:30
    cat hello.txt prints the whole file without opening an editor. Good for small files; for big logs use head, tail or less (Ch 11).
    Copy and move: cp, mv T 59:00
    ubuntu@linux: ~
    $ cp hello.txt

$ mv hello.txt demo.txt  # rename = move to a new name

    Moving around: ls, cd and mkdir -p
    Knowing where you are, getting where you want and seeing what's there. The course's favourite: ls -ltr, newest files at the bottom.

    Pipes and redirection: |, >, >>, <, <<, <<<
    Every command reads input and writes output. Pipes chain commands together; redirection sends output to files or feeds files and text into commands. This is the glue of every script.
    

    Remember2 min revise

    conn.close()

def transform_data(df):
    return df[df["age"] > 30]            # keep people older than 30

def write_data_to_file(df, output_dir="/home/ubuntu/extract"):
    os.makedirs(output_dir, exist_ok=True)
    ts = datetime.now().strftime("%Y%m%d_%H%M%S")
    path = os.path.join(output_dir, f"etl_output_{ts}.csv")
    df.to_csv(path, index=False)          # no 0,1,2 index column
    print(f"Data written to {path}")      # appears in the Airflow task log

    df = fetch_data_from_mysql()
    write_data_to_file(transform_data(df))

    ownerWho owns the DAG (default airflow)
    depends_on_pastTrue = wait until this task's previous run succeeded
    email_on_failure / email_on_retrySend an email when it fails / retries
    retries, retry_delayHow many extra attempts and how long between them. Failures are often temporary (file late, DB connection blip). Agree the number with your lead
    schedule_intervalHow often: every 5 minutes here
    start_dateFirst date it's eligible to run

    Interview & exam questions · 7
    Conceptcron vs Airflow?cron: time-based command runner, no UI, retries or dependencies. Airflow: workflow orchestrator with DAGs, retries, dependencies, backfill, history and a web UI.
    ConceptWhat is a DAG?Directed Acyclic Graph: a workflow of tasks and their order, defined in a Python file.
    ConceptWhat does catchup=False do?Skips runs for past intervals between start_date and when the DAG was switched on.
    ConceptWhy use a constraints file when pip-installing Airflow?To pin compatible versions of its many dependencies for your Python version.
    ScenarioWebserver is up but no tasks run. Why?The scheduler isn't running, or the DAG is still paused.
    ConceptWhere does Airflow store run history?In its metadata database (SQLite by default; MySQL/Postgres in production).
    ConceptWhy call a wrapper script from Airflow?Keeps orchestration separate from job code; the job can be run and tested on its own.

    R4Revision
    Pairs people mix up
    One line each. If you can explain every pair, you understand the course.
    

    Remember2 min revise
    • Most interview trick questions are one of these pairs.
    

    grep vs find
    Text inside files, vs files by name/type/size/time.
    > vs >>
    Overwrite, vs append.
    Hard vs soft link
    Second name for the same data (survives delete), vs shortcut to a path (breaks).
    cp vs mv
    Copy keeps the source; move (and rename) removes it.
    & vs nohup
    Background only (dies with the terminal's hang-up), vs immune to hang-up. Use both.
    kill vs kill -9
    Polite SIGTERM, vs forced SIGKILL.
    free vs available (memory)
    Unused RAM, vs RAM programs can actually get (includes reclaimable cache).
    apt-get update vs upgrade
    Refresh the list, vs install newer versions.
    ssh vs scp
    Remote terminal, vs remote file copy. Same port 22.
    bash vs sh
    Full bash, vs POSIX sh (dash on Ubuntu): arrays and ${1,,} may fail.
    ./s.sh vs source s.sh
    New child shell, vs your current shell (variables persist).
    = vs -eq
    String compare, vs integer compare.
    Single vs double quotes
    Literal text, vs variables expanded.
    $var vs $(cmd)
    Variable's value, vs a command's output.
    vi vs vim vs nano
    Minimal default, vs improved (colours, arrows), vs modeless.
    Terminal vs shell vs kernel
    Window, vs interpreter (bash), vs OS core.
    / vs /root vs ~
    Top of the tree, vs root user's home, vs your home.
    Absolute vs relative path
    Starts at /, vs from where you are.
    zip vs tar
    Compressed .zip, vs bundle (add z to gzip it; keeps permissions).
    Automation vs scheduling
    Code does the task, vs running it on time.
    cron vs Airflow
    Time-based runner, vs workflow orchestrator with retries, UI and history.
    Airflow webserver vs scheduler
    Shows the UI, vs actually runs the DAGs.
